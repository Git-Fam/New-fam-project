■ ファイル構成

- index.html
  公開画面。LP / スワイプ / 分析演出 / 診断結果 / 求人導線。

- line-complete.html
  LINE連携完了後の戻り先画面。

- terms.html / privacy.html
  利用規約 / プライバシーポリシー。仮置き事項はHTML上部にコメントあり。

- admin/index.html
  管理画面ログイン用の静的HTML。ログイン前は管理画面本体を含まない。

- config.js
  公開画面用の接続設定。管理用Secretは置かない。

- admin/config.js
  管理画面用の接続設定。管理用Secretは置かない。

- css/reset.css / css/styles.css
  リセットCSS / 画面デザインCSS。HTML/CSSは今後変更予定。

- src/app.js
  公開側JS。スワイプ、診断ロジック、Supabase保存、LINE導線、GAイベント送信。

- src/admin.js
  管理画面本体JS。マスタ保存、画像アップロード、画像軽量化、KPI取得。

- src/admin-login.js
  管理画面ログイン専用JS。ログイン成功後にadmin-uiから管理画面HTMLを取得。

- src/data.js
  初期マスタ。40問カード、診断軸、15タイプ診断結果。

- supabase/functions/*
  Supabase Edge Functions本体。

- supabase/dashboard/*-index.ts
  Supabase DashboardのEdge Functions Codeタブへ貼る用の単体ファイル。

- supabase/migrations/*.sql
  DB定義、KPI集計、自動削除Cronの控え。


■ 注意

- JSで使用しているid/class名は変更すると機能が壊れる可能性あり。
- JS使用中のid/class名はHTML内にコメントあり。
- 管理画面はログイン画面あり。ログイン前のHTMLには管理画面本体を入れない。
- 管理画面本体HTMLはadmin-ui Edge Functionからログイン後に取得する。
- 管理パスワードはSupabase SecretsのADMIN_LOGIN_PASSWORDにだけ保存する。
- セッション署名用SecretはADMIN_SESSION_SECRET。
- ログイン失敗は15分以内5回まで。超過時は15分ブロック。
- 管理画面はnoindex設定済み。
- 公開診断でユーザーに表示する質問・画像・結果文は完全な秘密にはできない。完全に隠すなら診断ロジックのサーバー側移管が必要。

- 公開側の基本体験を実装。

  表示数値、診断結果文章、スワイプ画像/質問内容、出題ON/OFF、新規質問、質問削除、質問数、AI会話設定を編集可能。

  ドラッグ&ドロップアップロード、ブラウザ側WebP軽量化、Supabase Storage保存、DBには画像URLとStorageパスのみ保存。
- 質問データを拡張。
  初期質問を100問に増やし、出題ONの質問から管理画面設定数だけ軸バランスを見てランダム出題するようにした。
- Supabase保存を実装。
  diagnoses / analytics_events / diagnosis_events / ユーザー単位データ / LINEアンケート / LINE会話履歴 / AI会話状態 / 相談依頼を保存。
- KPIと離脱集計を実装。
  日別 / 週別 / 月別KPI、診断タイプ別件数、離脱が多い設問番号を管理画面で確認可能。
- データ保持と自動削除を実装。
  未LINE登録のdiagnosesは短期保存、LINE登録済み診断・LINE関連データは180日保存、期限切れデータは毎日04:17 JSTに自動削除。
- LINE連携を実装。
  LINE Login / Messaging API / 2回目以降の再ログイン不要送信 / 4問アンケート / AI返信 / 相談CTA / 人間引き継ぎ停止まで対応済み。
- LINEアンケート完了メッセージをAI生成に変更。
  質問文 / 回答 / 診断タイプを元に自然な結果文を作り、AI失敗時は固定文へ戻す。
- 管理画面のユーザー確認機能を実装。
  診断結果、YES/NO履歴、LINE追加取得情報、LINE会話履歴、AI会話状態、相談ステータス、対応ステータス更新を確認可能。
- 法務・計測・セキュリティまわりを追加。
  利用規約 / プライバシーポリシー仮ページ、個人情報導線、GA4タグ、管理画面ログイン、ログイン失敗回数制限、noindexを追加。
- 管理操作ログを追加。
  DB保存と180日削除は残し、現在は管理画面表示とKPI API返却だけ一時停止中。

管理操作ログの表示を戻す方法:
導入目的:
- 管理画面を複数人で使う場合に、保存・画像アップロード・ログインなどの操作履歴を追えるようにするため。
- 設定変更や誤操作が起きた時に、いつ頃どの操作があったかを確認できるようにするため。
- 共通パスワード運用のため個人特定までは弱いが、最低限のトラブル調査用ログとして残している。

1. src/admin.js 上部の SHOW_ADMIN_AUDIT_LOGS を false から true に変更する。
2. src/admin.js をアップロードする。
3. admin-ui と kpi-summary には復元用コードが残っているため、通常は再Deploy不要。未反映環境では admin-ui / kpi-summary も再Deployする。
4. 表示をまた消す場合は SHOW_ADMIN_AUDIT_LOGS を false に戻して src/admin.js をアップロードする。

■ AIプロバイダー切り替えメモ

テストはGemini無料枠、本番はOpenAIへ切り替える可能性あり。
- 対象ファイル:
  supabase/functions/line-webhook/index.ts
  supabase/dashboard/line-webhook-index.ts

テストで使うSecrets:
  GEMINI_API_KEY
  AI_PROVIDER=gemini
  AI_MODEL=gemini-3.5-flash-lite
  LINE_AI_MAX_REPLIES=4

OpenAIへ変える場合:
- Supabase SecretsにOPENAI_API_KEYを追加
- AI_PROVIDER=openai / AI_MODEL=gpt-5-mini に変更
- line-webhook内のgenerateAiCareerReply()にopenai分岐を追加
- generateOpenAiCareerReply()を追加し、OpenAI Responses APIへ送信する
- Dashboard運用のため、同じ変更をsupabase/dashboard/line-webhook-index.tsにも反映
- line-webhookを再Deploy

Gemini/OpenAIいずれの場合もAIに送る情報は以下に限定する。
- 今回のLINE相談文
- 診断タイプ(result_type)
- LINEアンケートの希望条件
- 直近数件の会話履歴

AIに送らない情報:
- LINE user ID
- LINE表示名
- 40問のYES/NO履歴
- 6軸スコア

注意:
- Gemini無料枠は入力内容がGoogleのサービス改善に使われる可能性があるため、テスト時はダミー相談文で確認する。
- 本番運用ではOpenAIなど、有料APIで入力内容が学習利用されない設定/プランへ切り替える。

■ スペシャルクエスチョン確定仕様

- 通常カードのYES/NOではなく、A/Bどちらかを選ぶ「究極2択」形式にする。
- 例:
  Q.どちらの会社で働きたい？
  A.年収500万円でほぼ定時退社
  B.年収800万円で成果主義。忙しい
- 操作は通常カードと同じ。
  A側またはB側へスワイプして回答する。PCボタン / キーボード操作にも対応する。
- スペシャルクエスチョンも管理画面で編集できるようにする。
  質問文、選択肢A、選択肢B、表示ON/OFF、表示位置、表示順を管理画面から変更可能にする。
- 2か所固定にはしない。
  管理画面で何問出すか、どこに出すかを決められるようにする。
- 管理画面の「診断に使う質問数」は、通常カード + スペシャルクエスチョンの合計数として扱う。
  例: 出題数40、スペシャル2問ONなら、通常カード38問 + スペシャル2問。
- 診断タイプ判定に加点するかは別途判断。
  初期案はスコアには影響させず、LINE AIや求人導線の根拠として使う。
- 回答内容はDBに無期限保存する。
  ユーザー単位で、どの質問に対してA/Bどちらを選んだかを保持する。
  診断完了直後はLINE登録前のため、visitor_id / session_id / funnel_id / diagnosis_idで先に保存し、LINE登録後にuser_id / internal_user_idへ紐付ける。
- LINE連携時は、AIアンケート完了文やキャリア相談AIの文脈に使う。
  AIへ渡すのは質問文と選択肢ラベルに絞り、不要なIDや全回答履歴は渡さない。
- 見た目は通常カードと変える。
  `.special-question-*` など専用クラス名を使い、既存CSSとバッティングしないようにする。
- 画像や背景を画面いっぱいに広げるデザインになる可能性を考慮する。
  通常カードの親要素を壊さない専用wrapper / overflow / z-index / responsive制約を設計する。
