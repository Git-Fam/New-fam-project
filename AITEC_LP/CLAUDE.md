# CLAUDE.md

## プロジェクト概要

Figmaデザインをもとに、HTML・SCSS・JavaScript・PHP／WordPressでWebサイトを制作するためのテンプレートです。
作業開始前に `PROJECT.md`、`README.md`、`package.json`、対象ファイル、関連する既存コードを確認してください。

## 最重要ルール

- 指示された範囲だけを変更する。
- 既存のディレクトリ構成・命名・設計を優先する。
- 不要なリファクタリング、ファイル移動、class名の一括変更をしない。
- 既存コードを削除する前に利用箇所を検索する。
- 指示のないライブラリ・プラグイン・依存関係を追加・更新しない。
- 既存デザイン、文言、リンク先、挙動を推測で変更しない。
- 修正箇所以外へ一括フォーマットをかけない。
- コンパイル済みCSSを直接編集しない。
- 判断できない点は勝手に補完せず、未確認事項として報告する。

## 基本ワークフロー

1. 対象と関連ファイルを読む。
2. 類似実装と利用箇所を検索する。
3. 影響範囲を確認する。
4. 最小差分で実装する。
5. 構文・表示・動作を確認する。
6. 変更ファイル、実装内容、未確認事項を報告する。

## HTML

- セマンティックな要素を使い、FigmaのFrame数だけ不要なdivを増やさない。
- 見出し階層を保つ。
- 遷移は `a`、操作は `button` を使う。
- 画像には用途に応じた `alt` を設定し、装飾画像は空にする。
- JavaScriptのフックには原則 `js-` 接頭辞を使う。
- インラインCSSを追加しない。

## SCSS

- 現在の `sass/main.scss` と `@use` 構成を維持する。
- PCのFigma値には原則 `pmin()`、SPには原則 `s()` を使う。
- `pmin()` はPCサイズのみに反映する。必ず `@include pc {}` で囲む。
- `s()` はSPサイズのみに反映する。必ず `@include sp {}` で囲む。
- `pmin()` の値をそのまま `s()` に置き換えてSPへコピーしない。SPはFigmaのSP値、または既存のSP指定を使う。
- レスポンシブ指定は既存の `pc`・`sp` mixinを優先する。
- 変数・関数・mixinは既存定義を検索して再利用する。
- 色などの共通値は `_variables.scss` へ置く。
- ネストを深くしすぎず、目安は3階層程度までとする。
- `!important` は明確な理由がある場合だけ使う。

```scss
// OK
@include pc {
    font-size: pmin(16);
}
@include sp {
    font-size: s(14); // SPはFigmaのSP値
}

// NG: pmin() がメディアクエリ外
font-size: pmin(16);

// NG: PC値をそのままSPへコピー
@include pc {
    font-size: pmin(15.7);
}
@include sp {
    font-size: s(15.7);
}
```

## JavaScript

- 既存コードがjQueryかVanilla JSか確認し、同じ方式を優先する。
- 対象要素がないページでもエラーにならないようにする。
- グローバル変数とイベントの多重登録を避ける。
- CSSで十分なアニメーションは、まずCSSでの実装を検討する。
- 操作UIではキーボード操作と `aria-*` の更新を考慮する。

## PHP・WordPress

- 既存テーマ構成とテンプレート階層を優先する。
- URLは `esc_url()`、属性は `esc_attr()`、通常テキストは `esc_html()` を基本とする。
- HTMLを許可する値には用途を確認して `wp_kses_post()` を検討する。
- 入力値の検証、nonce、権限確認を行う。
- `query_posts()` は使わず、`WP_Query` 後は `wp_reset_postdata()` を行う。
- `functions.php` に大規模処理を詰め込まず、既存の分割方式に従う。
- ACFのフィールド名・返り値形式を推測しない。

## Figma実装

- デザインを勝手に改善しない。
- PC・SPの両方を確認し、Auto Layoutはflexまたはgridとして解釈する。
- gapで表現できる余白はgapを優先する。
- 固定座標やabsoluteを必要以上に使わない。
- 共通パーツは既存部品を再利用し、ページ固有コードと分ける。
- デザインのない中間幅でも破綻しないようにする。

## 明示的な指示なしで禁止する変更

- ディレクトリ移動、ファイル名変更、class名の一括変更
- CSS設計やWordPressテンプレート構成の再設計
- jQueryとVanilla JSの全面移行
- Sass関数・mixinの全面改修
- package.json、lockファイル、プラグインの更新
- プロジェクト全体へのPrettier実行
- 指示範囲外のSEO、文言、アクセシビリティ修正

## 利用可能なコマンド

- Sass監視: `npm run sass`
- 整形: `npm run format`
- 整形確認: `npm run format:check`

`npm run format` は広範囲を書き換える可能性があるため、明示的な指示なしに実行しないでください。
